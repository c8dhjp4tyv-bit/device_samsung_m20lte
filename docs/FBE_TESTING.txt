M20 LineageOS 22.2 FBE testing (experimental)
===========================================

Crypto startup
--------------
Recovery's prop.default build processing disallows ro.product.first_api_level.
init.recovery.crypto.rc sets it to 27 during early-init, before the version gate.
The ROM/SPL gate still rejects mismatches; do not replace it with future dates.
The recovery service runs m20lte-recovery-start, which waits for the checked gate,
Mobicore readiness, registered KM3/GK1 HALs, and the keystore2 Binder service.
The readiness probe performs service lookups only, never key operations.
On failure/30-second timeout, recovery starts with of_skip_fbe_decryption=true
instead of entering the unbounded DE-key Binder wait. Inspect the reason before
retrying; do not bypass a version mismatch or delete any encryption files.
Startup details are in /tmp/m20lte-crypto-startup.log in recovery RAM.

Keep keystore2 enabled
---------------------
TeamWin android-12.1 system/vold/Keymaster.cpp connects to keystore2 even for DE
keys. Its constructor uses AServiceManager_waitForService(), which explains the
splash hang when the service is absent. No device flag selects a direct KM3 path.
TeamWin android-12.1 system/security/keystore2/src/km_compat/km_compat.cpp explicitly
falls back from Keymaster4 enumeration to Keymaster3. KM3 itself is supported.
The recovery ramdisk needs /vendor/etc/vintf/manifest.xml, not just fragments.
Without the base, libvintf returns null; keystore2/src/vintf/vintf.cpp dereferences
that null in getHalNames()/getHidlInstances()/getAidlInstances(). A standalone
ARM64 probe using the exact CI library reproduced SIGSEGV without the base and
exited successfully with the base, listing keymaster, gatekeeper and health.
The installed Android 15 vendor manifest is schema 9.0, also rejected by the
Android 12 libvintf; the exact-library probe reproduced the same null crash with
that manifest. This explains continued crash loops after Fox mounts real /vendor.
The accompanying system/security patch makes all four FFI entry points return
an allocated empty list on null manifests (not a null pointer, which is invalid
for Rust's slice conversion even at length zero). KM3 fallback remains enabled.
CI applies patches/keystore2-vintf-null-manifest.patch before compiling. For a
manual source build, apply it from this tree to system/security with git apply
before building; it is NOT applied automatically to any local ROM source tree.
Actual phone boot and Android 15 credential decryption still require testing.
Sources: https://github.com/TeamWin/android_system_security/tree/android-12.1
         https://github.com/TeamWin/android_system_vold/tree/android-12.1
No independently verified working A12/KM3 Exynos recovery was found in the
reference-tree search; older android-9/11 trees do not establish an A12 workaround.

Kernel choice
-------------
Keep the current prebuilt kernel and DT unchanged for the normal 4.4-supported
recovery baseline. A /data filesystem written by the 5.10 port can have 36-byte
F2FS extra inode attributes; the current Fox 4.4 parser allows only 24 bytes and
rejects those inodes. This is not a PIN failure and cannot be fixed in the ramdisk.
For that filesystem, test a separate 4.4 f2fscompat kernel variant with the same DT.
The local m20-f2fs-extra-isize-compat patch accepts the newer extra attribute
layout only for uncompressed inodes; it does not implement F2FS compression or
make arbitrary newer filesystem features safe. Its changes are not upstreamed
or validated for every device/filesystem combination. Switching the general
prebuilt now would broaden an experimental filesystem backport to all users;
keep it a separate test variant until it has appropriate regression coverage.

SIGABRT investigation and diagnostics
------------------------------------
The second phone test confirmed automatic launch API, successful gate and KM3/GK1
registration, and no SIGSEGV. keystore2 instead aborts in a Binder worker. The
saved dmesg does not contain the abort reason, so a specific CHECK/panic is not
proven yet. Do not describe the remaining SIGABRT as fixed.
The first abort (~8.5 s) precedes the first /data mount (~37.4 s), ruling out the
later failed/ciphertext database copy as the cause of the initial abort. SQLite
accepts an empty file as a new database; zero bytes alone do not prove corruption.
Do not erase persistent Android databases or key files to investigate this.
The optional KM4 default probe precedes KM3 fallback in both Android 12 and 15
km_compat. Its missing-service message is not itself proof of an invalid KM3 HAL.
Candidate native aborts include getHardwareFeatures transport CHECKs, missing
mandatory declared services, or an invalid security level. Missing public
android.security.* services may simply follow failure to construct the mandatory
TEE security level before keystore2 registers its public services.

Fox 12.1 uses TWRP_INCLUDE_LOGCAT and TARGET_USES_LOGD in Android.mk (required
modules) and prebuilt/Android.mk (ramdisk binaries/libraries). The empty device
init.recovery.logd.rc override is removed so Fox installs its real service, which
starts logd on init. CI checks the installed service, binaries and flags and must
not trim logging out on a recovery-size retry.
A late-init service captures all logcat buffers to /tmp/m20lte-crypto-logcat.txt
before keystore2 startup, with 2 MiB rotations and two backups. RUST_BACKTRACE is
exported, but the existing custom Rust panic hook may still emit only panic text;
this is not a promise of a native backtrace. No /data tombstone redirect is used.
The km_compat diagnostic patch adds stage logs without changing fallback or
relaxing any CHECK. It records optional HAL lookup completion, KM3 fallback, and
hardware-feature query completion/version/security level. It never logs keys or
credentials. CI applies it alongside the existing VINTF null-manifest patch.

Next test (only with separate approval for flashing)
---------------------------------------------------
1. Back up readable data and EFS off-device. Do not format, wipe or change PIN.
2. Build the tree; verify the packaged base VINTF manifest, first-API init action,
   crypto-ready binary and recovery-start wrapper. For 5.10-written userdata,
   make a separate test image with the f2fscompat kernel, preserving the DT and
   Samsung boot-image fields/trailer. Flash only RECOVERY through Samsung tooling.
3. First verify init.svc.logd=running, init.svc.m20lte-crypto-logcat=running and
   a growing /tmp/m20lte-crypto-logcat.txt. Preserve that file and its .1/.2
   rotations, plus the startup log, dmesg and properties. Look for the actual
   fatal CHECK/Rust panic and the last km_compat stage; do not infer it solely
   from the optional KM4 lookup message.
4. Expect first_api_level=27, checked=1, Mobicore/KM3/GK1 and keystore2 running,
   crypto.ready=1, and of_skip_fbe_decryption=false without manual setprop/start.
5. The startup log must report registered services BEFORE it launches recovery.
   There should be no keystore2 signal-11 loop. Recovery should pass DE-key init
   and show its UI. If readiness fails, expect a usable UI with FBE skipped and a
   diagnostic startup log rather than a splash hang.
6. Try the existing PIN; confirm actual internal-storage files are readable.
   Reboot Android and confirm the unchanged PIN still unlocks and storage works.
   Returning to a known-good recovery cannot undo an accidentally upgraded key.
